## 一、最终定位与范围

| 工作台 | 职责 | 前台组织 |
| --- | --- | --- |
| 设计台 | 探索设计、保存版本、组织并确认三视角，交付样衣台 | 保留现有款式工作区，增加三视角交付区域，不复制新的生成平台 |
| 样衣台 | 接收设计，准备生产资料，推进打样、确认及生产跟进 | 款式资料 / 用料核价 / 打样生产 |
| 制版台 | 版师的知识、尺寸与计算标准中心；具体款式引用适用依据 | 查资料 / 查尺寸 / 算尺寸；当前款式上下文与最近使用作为辅助 |
| 资产库 | 共用图片与资料的查找入口 | 复用现有资产能力，不在三个台各建一套图库 |

产品原则：同款资料只填一次，按上下文自动带入；常用选项直接可用，高级规则按需展开。用户优先看到当前采用资料，内部准确记录版本与来源。交付、模型费用、样衣确认与量产采用有明确动作，普通查看和编辑不触发模型调用。

设计台交付样衣台必须有正面、背面、侧面三视角，不能为简化而取消。样衣台接收确认的设计，不承担新设计发散与多视角生成。制版台提供可应用的标准与工具，不替代样衣台的生产项目，也不要求另建重复项目。

## 二、代码现状与可复用能力

- 已有不可变设计版本、文字设计要求、父版本与图片来源关联；设计定稿、图片采用和工作版本已有独立含义。
- 已有参考图选择、模型能力管理、拍摄设置、原生输出尺寸/质量、服务端报价、持久任务、逐图状态、幂等及积分预留/结算/退款/待核对。
- 已有缩略图、等比预览、原图保存下载、归档回收站、权限及共享文件保护。
- 基线中样衣台、制版台均是 StationPlaceholder；本轮已替换为真实项目、标准尺寸及打样生产页面。
- 当前款式生成一次批次主要共用同一取景与来源上下文。三视角不能简单将张数设为 3：需要按输出位置记录取景、来源、结果与采用状态。
- 当前多用户以账户隔离与管理员权限为主。首轮沿用这一边界，公共标准与私有人体/项目资料分别授权；细分团队角色、跨组织协作不作为基础门槛。

## 三、统一数据与交互规则

1. 款式是贯穿入口。首次有效交付自动建立关联样衣项目；重复交付请求复用结果，后续交付修订进入原项目，不无故复制项目或覆盖旧资料。
2. 设计版本、设计交付修订、技术资料修订、纸样版本、实体打样轮次、生产批次分别记录；前台通过当前资料与统一历史入口访问，不要求用户反复填写内部编号。
3. 正式交付、已确认核价、样衣验收和生产采用资料保存快照。更新上游资料只提示可更新，不静默改变历史打样或生产依据。
4. 制版标准按品类、目标客群、客户要求等适用范围匹配；所有制版应用都有明确依据，不以一套公式强行覆盖所有服装。项目例外单独记录原因与确认，不污染通用标准。
5. 模特人体实测、标准人体号型、成衣尺寸及放码规则分清来源和口径；视觉上的模特/体型选择不等于真实测量数据。AI 图片不能证明尺寸、成分、工艺或真实合体程度。
6. 正常缺项使用中性状态说明；在提交对应动作时定位必要缺项。保持固定主要操作、清楚的选中反馈、可达关闭入口，不恢复全局常驻红框或多层滚动长弹窗。
7. 原图和纸样原文件保留，压缩只用于预览。新增引用必须同时纳入授权、生命周期与文件清理保护；先建立保护再开放新文件写入。
8. 普通业务成本采用货币与明确精度，模型调用仍采用现有积分体系，两者分开。缺失用量/价格不能按零成本处理，明确填写的 0 可以表示免费。

## 五、阶段 B：设计台三视角与交付

- [x] DESIGN-01 增加正面、背面、侧面位置及候选采用；支持已有图片、上传、缺图生成、局部补充和非对称款另一侧视图，查看大图与采用分开。
- [x] DESIGN-02 记录每个位置的设计版本、朝向、完整取景、展示方式、来源图与生成任务；统一背景、主体尺度与留白。旧图片与上传图以人工关联标识来源，不能伪造历史生成归属。
- [x] DESIGN-03 扩展现有报价与任务快照以支持不同视角的输出位置；默认共用同一设计基准，必要时引用已确认辅助图，不自动逐张串接最新结果造成设计漂移。
- [x] DESIGN-04 保留显式模型选择、兼容能力提示、原生尺寸质量、费用确认、实际进度、单位置失败重试和未知结果核对；采用已有图不调用模型。支持图片编辑不等同于已验证多视角一致性。
- [x] DESIGN-05 增加交付前核对：正背侧齐全、属于选定设计版本、结构/颜色/图案一致、AI 补全结构人工确认；三张重复图片不能冒充三视角完成。
- [x] DESIGN-06 保存设计版本、采用的原图引用、属性、文字说明及必要参考资料为固定交付修订；显式“交付样衣台”自动建立或更新关联项目，并可直接前往项目。
- [x] DESIGN-07 后续新设计通过新交付修订提示项目更新；当前采用图、历史交付与生产基线不自动替换。三视角中未定义的真实尺寸/工艺留待补全，不从图片编造。

验收：正背侧各有正确的取景与归属；缺一视角不能交付；选图、看图不产生费用；部分失败只重试失败位置；重复交付只产生一个有效结果；上游修改不改写已交付资料。

- [x] PROJECT-04 管理本款纸样原文件、适用尺码、版本、修改说明和采用状态；常用图片/PDF按能力预览，纸样原文件可下载。三台引用同一资料，不分别上传维护副本。

## 七、阶段 D：制版台标准、尺寸与计算

- [x] PATTERN-01 用“查资料 / 查尺寸 / 算尺寸”替换制版占位页；提供搜索、分类、最近使用和当前款式上下文，不新增必须单独创建的制版项目。
- [x] PATTERN-02 知识条目支持品类/部位/问题、做法图示、来源和适用范围；参考资料与正式标准明确区分，能跳转相关尺寸定义和计算工具。
- [x] PATTERN-03 提供轻量维护入口：草稿、发布、历史版本及停用；正式标准发布后保留原版，修改产生新修订。按适用条件推荐依据，版师核对后应用；特例保存原因与确认。
- [x] PATTERN-04 同一尺寸工作区组织模特实测、标准人体号型、成衣尺寸及放码规则；统一部位代码、测量起止点/示意、整围半围、单位、精度、公差与来源。
- [x] PATTERN-05 模特档案保存测量日期、体态说明及历史；人体测量与生成图中的模特外观分开；本款成衣调整不改写人体原始测量或其他款式。
- [x] PATTERN-06 支持常用尺寸表维护/导入、基础尺码及放码规则应用、引用到本款尺寸表；单位转换口径明确，缺项可见，不把未确认数据当正式生产依据。
- [x] PATTERN-07 首轮提供预置的单位换算、松量、缩率及放码增量等常用计算工具；每项明确适用条件、变量、公式、过程、单位、舍入及结果。采用确定算法，不用模型猜数、不执行用户任意脚本。
- [x] PATTERN-08 从当前款式已确认数据自动带入计算输入；保存输入、规则版本、结果与人工调整；结果写入本款资料，查看和计算不产生模型费用。
- [x] PATTERN-09 每款关联适用标准、目标人体/号型与尺寸依据；设计台可在准备交付时选择或查看，样衣项目可直接打开对应工具；标准更新提示选择采用，不自动修改在用资料。
- [x] PATTERN-10 整理首轮知识、尺寸和公式的数据来源，优先用户确认资料与可核对来源；没有真实数据时提供可维护空态。演示尺寸和未经核对的示例不能自动发布为生产标准。

验收：版师可从一处查到部位规则、尺寸和相关公式；每个制版应用可追溯；人体、成衣与放码口径清楚；公式结果可复算；新标准不改旧项目；无标准资料时不会伪造“已符合标准”。

## 八、阶段 E：用料核价与 SKU 联动

- [x] COST-01 面料、里料与辅料共用材料明细，维护名称、规格、计量单位、单耗、损耗、单价及来源；按需区分颜色/尺码适用范围，不要求先维护独立供应商库。
- [x] COST-02 填用量与单价即计算材料成本，补充工价、后整、包装及其他费用；明确单耗是否已含损耗，防止重复加成；缺价/缺用量显示待补，明确的 0 单独处理。
- [x] COST-03 采用货币与固定精度的服务端计算，单位换算可核对；首轮保持单一核价币种，混合币种不得直接相加。生产成本与生图积分分开。
- [x] COST-04 SKU 引用材料适用条件形成单件成本；数量矩阵汇总计划数量与成本。公共单耗默认共用，确有差异时才录入覆盖值。
- [x] COST-05 核价草稿可修改，确认后保存所用价格、用量、规则与结果快照；材料涨价形成新核价，旧打样和生产确认价不被覆盖。

验收：材料无需重复抄到核价；单件/整批、损耗、精度和 SKU 差异计算正确；缺价不当免费；旧确认成本可复算且不会随现价变化。

## 九、阶段 F：实体打样、确认与生产跟进

- [x] FLOW-01 管理首样、二样等轮次，关联本次采用的设计、工艺尺寸、纸样与资料修订；制作方、交期、费用按实际工作补充，不成为新建项目时的长表单。
- [x] FLOW-02 上传原始实拍、测量记录与试衣说明，按正背侧/部位与设计基准对照；桌面并排、手机切换，不同构图不强制叠图；用户已有实物可以在项目内直接登记。
- [x] FLOW-03 图片部位编号与问题清单关联，记录意见、处理情况、修改要求和解决依据；下一轮带入未解决问题，上传新图不自动判定问题已解决。
- [x] FLOW-04 明确补充资料、需要修改、样衣确认通过和停止打样；设计改变返回新设计版本，技术调整形成技术修订，制作偏差进入新样衣轮次，历史各自保留。
- [x] FLOW-05 量产前核对并固定采用的设计交付、适用标准/尺寸、工艺、面辅料、纸样、SKU、核价和样衣确认记录；必要缺项在该操作时定位，适用性差异明确记录，不增加多级审批。
- [x] FLOW-06 建立生产批次、SKU 数量矩阵、制作方、交期及常用生产阶段；记录阶段时间、数量、异常与完成情况，阶段计数不相加冒充成品总量，样衣数量与大货数量分开。
- [x] FLOW-07 生产批次引用固定资料；后续修改建立新修订并明确后续批次采用关系，不重写已开工/已完成批次。记录完成与验收结论，归档可恢复，文件清理独立处理。

验收：首样→问题→二样→确认可完整追溯；样衣确认不等于已投产；量产提交重复请求不建重复批次；计划与 SKU 合计一致；资料修改与归档不破坏历史依据和原文件。

## 十、贯穿交互与易用性验收

- [x] UX-01 三台保留清楚职责，默认带上当前款式；用户不重复建项目、填写名称或挑选多套内部版本；当前采用资料与历史有明确区别。
- [x] UX-02 常用表单短而集中，按工作阶段补资料；高级规则和长历史折叠；每个场景只有一个主要动作，提供明确返回、取消和草稿保存状态。
- [x] UX-03 模型与输出控件共用、记忆选择、可查看与更换，报价保持服务端权威；手工资料录入、尺寸计算、看历史不调用模型。

## 十二、执行依赖与阶段完成标准

顺序：A 共用基础 → B 三视角交付 → C 项目与资料 → D 制版标准与尺寸工具 → E 用料核价 → F 打样与生产。UX、迁移及专项验证随各阶段执行，最后完成跨台验收。

- B/C 可先组成“设计交付→项目接收”的可检查闭环；此时未完成的核价或生产功能不能显示为已可用。
- D 为正式尺寸、标准应用和量产依据提供支持；E 依赖 C 的 SKU 与资料结构；F 的量产确认依赖前面各项可追溯资料。
- 功能分阶段交付不等于从本轮总 TODO 中删除后续阶段。当前第一轮目标包含 A–F 的基础完整流程，复杂扩展见下节。
- 内容数据与系统功能分开验收：可先实现维护、引用和确定计算能力；生产标准必须有真实来源和专业核对，不以虚构种子数据填满页面。
