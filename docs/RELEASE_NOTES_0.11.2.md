# Fashion Studio 0.11.2

本版修复管理员删除模型后仍显示“已停用”、且无法重新添加同 ID 模型的问题。

## 行为

| 操作 | 管理列表 | 用户可选 | 同供应商再次添加同模型 ID |
| --- | --- | --- | --- |
| 下架模型 | 保留，可上架 | 不可选 | 提示恢复或删除现有记录 |
| 删除模型 | 移除 | 不可选 | 允许，生成新注册 ID |
| 停用供应商 | 保留供应商及模型，标明不可用 | 其下模型均不可选 | 先启用供应商 |
| 删除供应商 | 移除供应商及其下模型 | 均不可选 | 可新建供应商及模型 |

历史计费、任务、生成记录、原图及旧注册 ID 保留，不因同名重建而改变。删除的记录不能重新激活、编辑或测试。后台默认与回退模型引用在失效时清理；其他有效供应商仍提供同名聊天模型时保留其配置。

同时修复编辑重名绕过、供应商类型不匹配、新建供应商忽略启用开关、编辑未刷新模型缓存、切换供应商后迟到响应覆盖选项、只读模型输入框仍能通过残留下拉修改等问题。补齐操作中状态、删除失败保留编辑内容和手机操作区换行。能力摘要区分未验证、验证失败、配置变化和模拟结果；未声明的能力禁用对应测试按钮。删除供应商时清除其加密凭证和模型缓存。

## 升级

服务启动时为 `providers` 和 `models` 增量添加可空 `deleted_at` 字段及查询索引；迁移在事务中执行并可重复运行，不删除旧行、不改写历史模型 ID，不自动重命名或清理旧的停用记录。部署流程已有升级前数据库与上传文件备份。

旧版只有启用状态，不能识别当时点击的是“删除”还是“下架”。升级后请对需要移除的旧停用记录再点击一次删除，然后重新添加需要的模型。
