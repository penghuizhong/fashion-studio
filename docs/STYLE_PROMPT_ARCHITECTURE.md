# 款式衍生提示词架构重构

## 参考文档的取舍

参考用户上传的《ShopixAI服装工作室-完整提示词架构》，采用全局规范、模块设计内容、九维参数与自然语言画面描述分离的设计。原文中第三方系统提示词明确为截断后推测，本项目的执行规则自行定义，不声称还原该系统。文档称“九维”的内容是九个设计维度，图片类型由模块单独提供。

文档中的“全部模块必须露脸”与平铺、挂架、纯文字模块矛盾，执行时以模块任务为准。继续保留本项目的主图完整服装取景、主图不新增文字、商品卖点原图裁切排版、保真与创意模式区分。天蓝丝绸长裙、固定色号、字体、示例模型和固定积分均为文档样例，不硬编码成所有款式的默认配置。积分继续来自实际模型报价。

## 数据与执行

保留现有五步流程和规划数据结构，无数据库迁移：

1. **执行规则**：设计职责、事实优先级、参考角色分工、模块例外和禁止虚构资料。
2. **整体设计规范**：视觉基调、摄影、主体、服装、文字、事实边界，整套图片共用。
3. **本图设计内容**：模块 ID、定位、模块内张数、专用规则与九维表格；参考图分工、商品事实及边界一起编排。
4. **画面描述**：每图 `requirement`，描述主体、服装、姿态、环境和画面重点。
5. **用户生成要求**：本次输入与分析观察，区分事实与创意建议。
6. **生成参数**：沿用所选尺寸与质量，模型调用参数和费用仍由现有生成任务管理。

`shared/stylePrompt.js` 提供公共编排函数；`server/src/stylePlanCore.js` 将 `spec` 与全局规范编译为最终提示词，并返回派生的 `prompt_layers` 供界面核对。层信息不参与手工草稿保存。报价和任务继续冻结最终提示词，不在提交后重新编排。

每图九维：主体识别、服装识别、试穿策略、构图、光影、背景、配色、文字、视觉氛围。主图或纯视觉模式的新增文字不会从参数表注入。平铺、挂架和纯文字模块不会继承全局人物一致性描述。设计参数与文案的 API 修改也被记作手工修改，重新分析先保留候选结果，需用户明确采用才替换。

完整手工提示词保留原有优先执行行为；修改全局规范或逐图参数会使其过期，需重新编排或确认保留。旧手工提示词也可能因本次自动编排规则变化而提示同步，不自动覆盖。

## 方案预览

从上到下显示：核对概览 → 整体规范 → 逐图卡片 → 本次费用。逐图卡片将画面描述、九维设计内容、自动六层提示词与手工完整提示词区分展示。缺资料的卡片即使折叠也显示具体缺项，并可返回需求分析补充；这些图片不计入本次生成张数和费用。底部保留唯一费用确认生成入口。
