# 款式衍生提示词架构与合并说明

## 与远端 0.17.3 合并

以远端的精简执行方式为准：每图只有 `description_prompt`（主要描述）与 `attributes_prompt`（基本属性），每段最多 200 个 Unicode 字符。生图提示词由这两段与非空整体规范直接拼接。尺寸、质量、参考图片仍使用独立请求参数。单次只生成当前模块的一张图，不恢复冗长规则注入、跨模块任务串入或额外风险勾选。

本次保留并整合的改动：

- 预览页先显示方案概览和整体设计规范，再显示逐图卡片。
- 折叠卡片也显示具体缺失资料；可直接返回需求分析补充。待完善图片不计入本次张数和费用。
- 底部保留唯一费用确认入口，移除内容区重复生成按钮。
- 每图提供九维分析资料的只读核对视图，以及实际执行提示词视图；编辑执行画面仍使用两段精简提示词，不同时维护两套生图要求。
- API 修改九维资料或文案时同样记录为手工修改；重新分析不静默覆盖。空九维字段的格式归一化不会被误判为手改。
- 九维资料只作为分析上下文 `design_reference`，不直接拼入生图提示词。原图冲突必须报告，不能将规划参数直接当作商品事实。
- 远端真实图片附件、图号重排、来源追溯、单图请求与模块隔离检查保留。

无需数据库迁移。历史长提示词按远端方式重新分析，不将旧长文本无声当作两段精简内容。

## 上传文档的采用与取舍

参考《ShopixAI服装工作室-完整提示词架构》的分层思想：任务规则、全局规范、模块设计、画面描述、用户要求和生成参数各有来源。分析阶段使用这些信息，执行阶段遵循 0.17.3 的精简接口；不将六层原文逐图重复注入。

第三方完整系统提示词在文档中明确为截断后推测，本项目不声称还原。所谓九维为主体、服装、试穿策略、构图、光影、背景、配色、文字和氛围；图片类型由模块提供。文档的天蓝礼服、色号、字体、示例模型与固定积分均不硬编码。

“所有模块必须露脸”与平铺、挂架、纯文字模块矛盾，以模块任务为准。保持商品结构和颜色，不把面料外观当作真实成分，不凭空添加拖尾、背面或工艺，不虚构品牌与服务资料。主图无新增文字，卖点页沿用原图裁切排版。

## 验证

`npm --prefix client run check:theme`、前端构建、后端 CI 检查和浏览器套件。新增桌面/移动测试覆盖规范顺序、缺品牌资料、单一生成入口、九维资料核对、实际执行提示词、两段编辑持久化和补充资料导航。后端新增测试覆盖空参数归一化、手工保护及“分析资料不扩张执行提示词”。本地 fixture 验证不代表真实供应商的生图质量。
