# 万能画板

## 已实现的第一版

在侧边栏打开“万能画板”。首次进入创建画板；支持新建、切换和重命名。进入后默认收起应用侧栏，为画布留出空间，可从左上角展开。

- 无限画布、平移缩放、多选、图片、文字、形状、箭头、铅笔、橡皮、裁剪、图层显示/锁定/排序、复制、删除、撤销重做、PNG导出。
- 上传、拖拽或粘贴位图；从“我的模特”“已上传”“画板图片”“款式当前版本”“商品图”添加已有图片，不重复复制原文件。
- 选中图片后添加编号引用，Shift 可多选。编号与模特/服装/风格角色分开管理。当前图片裁剪和翻转同样作用于实际生成附件。每次任务原始及处理后的参考图合计均限制32MB，并逐张处理以控制内存。可将选中图片存为模特，供其他画板和款式直接复用。
- 可直接生成，也可在“参数”中选择视觉分析模型。分析只允许一个生成步骤或一个澄清问题，不执行任意工具。每画板一个会话，保留最近四轮的文字上下文；之前的图片只有再次引用才会发送。
- 先报价，再确认执行。分析额度是上限预留，成功后按返回用量结算（不超过确认金额）；供应商缺失用量时使用已显示的分析预留上限。澄清只结算分析，不调用图片接口。
- 生成占位、SSE进度及轮询补偿、结果落位、前后对比、来源血缘和缩略导航连接。
- 保存成功任务为单步工作流、命名和删除；可载入参数重新绑定全部图片，或批量替换一个输入槽位，其余参考图保持不变。每批1～20张，必须确认总预算。批量复跑直接执行已保存提示词，不再次调用Agent改写步骤。
- 品牌套件保存视觉要求和最多8个色值。品牌Logo需作为图片引用显式添加。
- 7天只读分享，可撤销；新建分享会使原链接失效。分享者应明确：持有链接的人可以查看画布内容和其中使用的图片。页面编辑后分享视图随最新已保存快照更新。

## 存储和恢复

SQLite 的 `canvas_projects` 保存 tldraw document 快照，不保存相机和选择状态；新开时适应画板内容。快照包含业务版本1及 tldraw 的序列化 schema，可由固定版本内核执行支持的迁移。尚无旧产品画板需要迁移；升级 tldraw 前必须用已有快照做兼容测试。

`canvas_assets` 引用 DATA_DIR 下的图片；`canvas_project_assets` 关联画板并保留文件，删除其他款式记录不会清理已被画板引用的图片。备份必须包含整个 DATA_DIR 的数据库和 uploads，不能仅备份快照JSON。上传/生成使用原图和缩略图存储，字体和内核资源从本应用同源加载，不依赖外部资源CDN。

自动保存防抖1200ms，串行请求并携带 expectedRevision；版本冲突返回409，不自动覆盖或丢弃本地内容。浏览器保存按账号、画板隔离的未保存快照草稿；恢复旧版本草稿时需另存新画板。浏览器存储空间耗尽时可在错误提示中导出快照；清理浏览器数据会删除未上传草稿。草稿可能含图片访问路径和文字内容，公共设备应退出账号并清理浏览器数据。

运行通过 `canvas_runs`、`canvas_steps`、`canvas_asset_events` 保存，任务认领与额度预留在事务中执行。全局最多并发2项；同一用户的普通提交同时只允许一项，已确认批量可排队。工作进程启动及定时器会认领排队任务；已派发任务失去租约后置为 uncertain，禁止自动重新出图。

单用户的个人分析Key只在任务内存上下文中保留，不写入报价、快照或数据库；服务重启后，这类未开始的任务明确失败并释放预留额度。多用户个人Key按已有账号设置解析。供应商或价格变化会要求重新报价/提交，不能静默切换。

服务端先保存结果资产，再由浏览器按确定性 shape ID 放置，强制保存快照后回填 delivered。保存失败仅补持久化；已经回填的结果被用户删除后不会因轮询重新出现。输入资产版本、角色、裁剪以及实际传输数量保留在请求/结果追踪中。

## 停止、错误与结算

停止排队任务会退回预留；已发送上游请求无法保证撤销，最终结果仍会保存并结算。停止分析后，图片尚未派发时只结算已完成分析。

明确拒绝的请求释放未消耗额度。断网、超时或其他不能确认供应商结果的错误进入 uncertain，保留额度。相同图片、要求和模型的任务在核对前不能重复启动。

管理员（单用户模式为本机使用者）核对供应商账单后，可调用：

```
POST /api/canvas/runs/:id/reconcile
{ "action": "refund", "reason": "已核对供应商未产生消耗" }
```

确认发生消耗则 action 为 charged。接口要求原因、校验管理权限并防止重复结算；不要未经核对调用退款。平台上游无法查询任务时，不会假设失败并自动重发。

## 部署配置

- 新表使用幂等增量建表，无需迁移现有业务数据。
- 前端固定 `tldraw` 和 `@tldraw/assets` 3.15.6，兼容 React 18。
- **tldraw 是商业许可 SDK。依赖安装不等于获得生产许可。** 上线前需要核对适用许可并配置合法的 `VITE_TLDRAW_LICENSE_KEY`（前端构建变量）；保留内核自带的许可与水印处理。没有替用户申请或购买许可。
- 图片、分析模型继续在现有模型管理中配置。双图任务需要模型支持至少2张图片，Agent分析需要视觉模型。
- `canvas/shared/` 是基于随机分享令牌的公开只读接口；其余画板API沿用现有会话鉴权。原图路径在公开快照中替换成分享令牌图片接口，仅允许读取公开快照中使用的资产；隐藏对象及其子对象、无引用资产不进入分享快照。
- CSP 允许同源 blob 图片/读取，用于内核本地预览和导出；不开放任意远程图片代理。Vite 不内联资源，避免翻译JSON受 data URL 连接策略限制。

## 验证

`npm --prefix server run check:canvas` 检查账户隔离、资产访问与保留、CAS冲突、分享撤销、两份上游图片字节、裁剪、品牌冻结、幂等计费、失败退款、未知结果核对、停止、Agent用量、澄清、工作流预算及批量幂等、租约恢复和串行保存。

`cd client && npx playwright test tests/canvas.spec.js tests/canvas-sharing.spec.js` 覆盖桌面/手机上传、保存恢复、冲突另存、双图Agent生成、工作流保存、对比及刷新不重复放置，以及跨画板模特复用、只读分享与撤销。

测试使用隔离数据库和模拟供应商，不调用真实付费API，不能替代实际供应商的视觉质量验收。
