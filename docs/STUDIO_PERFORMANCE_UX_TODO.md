### 核对到的实际行为

- “从款式或资产选择”实际包含当前款式原图、已有生成图及已上传参考；跨款式资产通过另一个“从资产库添加参考”入口转入。入口及命名重复，组件和数据源也未统一。
- “本次要求包含服装设计变化”用于将文字设计要求保存为新版本的设计说明；保存时沿用当前结构化属性，不会自动理解文字并更新属性。换色/改细节已有独立保存版本区域，使这一选择更难理解。
- “从当前属性整理要求”只在本地拼接前六项属性，不调用模型。生图提示词本来就包含完整版本属性，重复追加会增加冗余；追加逻辑还会静默截断到 1200 字符。
- 整理要求后的预览 textarea 未套用统一表单样式，取消按钮也缺少统一按钮样式；资产库的额外选择框同样存在原生控件样式混入。切换衍生动作还会清空本次要求，存在输入丢失风险。
- 白底商品图目前是生成基础图/换场景下的附加勾选项，任务层级不清楚。
- 管理端分档价格直接编辑 JSON。服务端一旦启用分档，未命中的尺寸/质量组合会拒绝报价，不会自动回退到统一单价；更具体规则优先，同优先级不同价格可能冲突。
