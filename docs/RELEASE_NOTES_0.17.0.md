# 0.17.0 商品图保真与卖点排版

## 实际行为

五步界面不变。需求分析新增“同款商品保真 / 创意设计”。同款模式必须有商品图，缺图不能分析或提交，不会退化成只根据属性文生图。可选模特图发送真实图片；人物编号没有绑定图片时会提示核对。

主图展示默认调用所选模型的图像编辑：单主体、完整服装、静态姿态、无新增文字和拼图。实际生成仍取决于供应商模型能力，规则不能保证换装后的商品结构绝对一致。

款式卖点默认走原图排版：主展示配1–4处真实裁切，文字由 Noto Sans SC 字形路径绘制，产品局部不经过图像模型重画。生成此类排版不调用生图模型，模型积分为0。商品原图、人台图可直接做主展示；系统生成的主图必须先逐项验收。已生成的细节素材仍需核对来源，推荐原始实拍图，不能把生成纹理当作真实面料证据。

## 操作

1. 需求分析选择商品原图、可选模特图及主图/款式卖点模块。分析会给出整体规范和每图方案。
2. 方案预览可查看本图参考缩略图。事实冲突或可能改变材质、结构的指令要求核对；修改图片引用后需要再次核对。
3. 款式卖点卡内修改标题和逐字说明，选择每处来源及裁切百分比，核对并确认。可调整配色、字号、主图左右位置和留白。字号按1024像素宽画布计算，导出512像素时会等比缩小，建议上架使用1024或更大尺寸并放大检查。
4. 点击“预览排版（不调用模型）”，确认真实细节及中文。缺少卖点、裁切越界、未确认、字形不支持、文案溢出或文字对比不足都会阻止提交。修改裁切/文案会清除该项确认。
5. 结果页查看实际调用依据，逐项检查结构、配色、面料、图案、人物、构图、文字。全部通过才能标记已验收。未通过需说明问题，修订记录保留。
6. 卖点结果可返回裁切与文案重排，不需要重新生成人物；新结果独立验收。

文字以结构化排版数据保存，可修改后重新导出PNG；没有自由拖拽画布、PSD导出或自动OCR修复。文字对比度有阈值校验；图片遮挡及源图清晰度仍需人工核对。字体许可证为SIL OFL 1.1，由npm依赖提供，不依赖服务器系统中文字体。

## 请求与数据

- 报价冻结每图参考图片角色、顺序、SHA-256、尺寸及提示词；提交和执行前再次核对文件摘要。结果记录实际调用模型、尺寸、质量、引用和合成来源，不记录API密钥。
- 新增 `style_image_reviews` 表，以图片与修订号保存验收历史，启动迁移可重复执行。保留旧规划、图片和计费数据。
- 新增依赖 `fontkit`、`@fontsource/noto-sans-sc`。部署须执行 `npm ci --prefix server`；更新前按原备份流程备份数据库和uploads。旧代码回滚可保留新增表，不能继续编辑新排版任务。
- 原有报价、积分、任务幂等与不确定结果处理沿用。原图排版仍使用任务队列与结果记录，纯排版本身不收模型积分。

## 模型对照

在实际服务创建蓝裙、西装、印花服装三个带原图的款式，复制 `PRODUCT_IMAGE_BENCHMARK.example.json`，替换款式ID与模型注册ID。每组固定尺寸，只比较模型或质量档；不同尺寸另开测试组。

```bash
cd server
node scripts/benchmark-product-images.js --manifest comparison.json --output report.json
# 首次仅创建测试规划并取得报价，不运行图片模型。
node scripts/benchmark-product-images.js --manifest comparison.json --output report.json --resume --execute --max-points 100
```

多用户会话通过环境变量 `BENCHMARK_COOKIE` 或 `BENCHMARK_TOKEN` 提供，报告不写入凭证。执行需同时指定预算；报告记录每配置三个样本各三次的来源、实际请求、成本与耗时，人工补充逐项验收和返修时间。中断后原任务幂等续跑，结果不确定时停止后续调用；不要重新创建报告盲目重跑。

本轮未接入生产数据库或真实供应商密钥，未进行真实付费模型对照，因此没有更换默认模型，也未宣称达到Shopix视觉效果。蒙版局部修复、自动视觉评分、OCR修复、原图清晰度自动诊断仍待实施。
