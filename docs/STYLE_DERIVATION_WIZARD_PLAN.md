# 款式衍生五步工作流：设计与实施方案

状态：0.12.0 本地实现与自检完成，未推送发布。实现基线：0.11.2 / `main` / `db95d47`。

本方案汇总五步流程、左右分屏、详情模块数量选择、逐图提示词管理和整体设计规范。实施任务以 [执行 TODO](STYLE_DERIVATION_WIZARD_TODO.md) 为准；此前已发布的版本、原图、任务、积分和文件引用保护继续有效。本轮已按方案实现，前后端和锁文件同步0.12.0；实际证据见TODO，升级与限制见 [发布说明](RELEASE_NOTES_0.12.0.md)。未调用真实付费模型，未推送或部署。

## 一、目标与范围

主流程：款式属性 → 需求分析 → 方案预览 → 生成中 → 完成。

步骤2收集已保存设计、参考图、商品要求、模块数量及输出条件，分析后形成步骤3的整体规范和逐张规划。步骤3是用户审核、调整与确认费用的核心页面。

整体布局采用左侧输入、右侧预览。新增内容包含商品分析、19类模块、结构化图片规划、公共设计规范及逐图最终提示词；继续复用现有注册模型、供应商能力、报价、后台任务、账本、版本和图片能力。

既有基础生成、自由衍生、换色、改细节、细节图、换场景、白底商品图和再生成应迁入五步流程。保留快速单图任务，允许只选一个模块/一张图。修改服装设计由步骤1保存新版本；展示方向与内容数量在步骤2组织，不重新堆叠整页动作卡和重复的生成方式选择器。

三视角交付继续使用专用正/背/侧位置、同版本核对及样衣项目衔接，商品详情图数量和完整性不能替代设计交付条件。

本轮不恢复已下线的图文排版 tab、自由画布、SVG/PNG 排版导出或旧 layouts API。规划预览采用现有图片及构图示意；新增文案随生成要求交给图片模型，说明字体精度与参考一致性属于模型能力，不能保证精确排版。

## 二、统一弹窗与响应式布局

- 固定标题栏、右上角关闭、五步导航和底部操作栏；左侧建议38%、右侧62%，右栏优先保证图片规划编辑宽度，比例通过布局变量维护。
- 左右正文分别是各自的滚动容器；弹窗外层和卡片内部不再出现额外纵向滚动。固定区域与两列使用 flex/grid 分配高度。
- 步骤3可收起左栏并保留展开入口；不默认引入第三列。右栏通过“图片规划 / 构图预览”切换内容，选中图片编号保持一致。
- 窄屏使用“设置 / 预览”视图切换并保留位置，不把桌面两列挤成窄栏；底部适配安全区和软键盘。
- 主操作始终在右侧，“上一步”在左侧；只读查看、返回步骤和关闭不提交任务。已完成步骤可返回，后续步骤按前置条件开放。
- 原图查看入口继续先打开轻量预览；五步功能与版本浏览在同一款式详情内展开，不再层层弹窗。属性入口打开步骤1，版本历史通过步骤1的版本浏览入口访问。
- 所有颜色使用 `theme.css` 语义变量，深浅主题一致；卡片的选中、悬停、焦点、禁用和处理中可辨，点击区域和键盘操作可达。

| 步骤 | 左侧 | 右侧 | 固定底部主操作 |
| --- | --- | --- | --- |
| 1 款式属性 | 版本选择、属性、修改草稿 | 当前版本关联图片/明确标注的父版参考 | 下一步；有修改时先显式保存为新版本或放弃修改 |
| 2 需求分析 | 参考图、生成要求、详情模块、生成参数 | 待分析引导、真实分析阶段、已完成规划摘要 | 分析商品并生成方案 / 重新分析 |
| 3 方案预览 | 输入摘要，按需展开修改 | 整体规范、逐图规划、构图示意 | 确认费用并生成 N 张 |
| 4 生成中 | 本批次设置快照 | 逐图状态及已完成结果 | 查看已完成结果；返回只读查看 |
| 5 完成 | 当前批次、历史、模块筛选 | 完整图片预览、下载与继续衍生 | 按当前选择提供下载或新一轮生成 |

## 三、步骤1：款式属性与版本

1. 版本选择显示编号、父版本、修改摘要、时间和定稿状态；选择版本同步更新属性和图片关联。查看版本不隐式切工作版本或封面。
2. 已保存属性与初始识别快照不可覆盖；点击“基于此版本修改”进入草稿，整次编辑保存一个新设计版本。无变化不新增版本；并发和请求重发沿用现有保护。
3. 基础属性使用合适的文本、枚举和多值控件。人工修正、识别来源和未知项可区分，设计变化说明可随版本保存。
4. 未保存修改可暂存，但不能作为已保存版本进入后续生成；下一步提供明确的保存/放弃处理，不在导航时静默建版或调用模型。
5. 新版本无图显示“尚未生成”；父版或其他版本图片只能标为参考。历史图片缺少可靠版本关联时继续标为未记录，不自动归到V1。
6. 预览可压缩，文件保存与下载使用模型原图；完整展示、不裁切、不拉伸、不按新比例重新保存原文件。
7. 从旧结果继续衍生时固定其版本和底图，草稿恢复与异步加载不得覆盖用户刚选中的图片。

## 四、步骤2：需求分析输入

### 4.1 参考图片

一个添加入口提供上传、当前款式/版本图片、资产库来源。参考图角色包括款式主体、参考模特、面料细节、场景风格；支持排序、移除、预览和编号说明。每张图有稳定引用ID，图号是当前显示顺序；排序后更新图号关联，不能让“图2领子”的含义悄悄漂移。检测到编号说明受影响时要求核对。

默认主体明确展示且可更换；不额外生成“辅助参考图片”区域。数量服从所选图片模型能力，禁止静默丢图或自动换供应商。分析模型如需识图，也单独校验其视觉能力和可用输入上限；必要时让用户选择分析图片，不能假装分析过未发送的图。

### 4.2 生成要求

主输入提示：“写下商品卖点，以及你希望看到的画面。”保存用户原文，已确认款式属性由系统引用，不要求重复填写。品牌、促销、售后、尺码和成分资料按已选模块补充，不再一次展开全部字段。

步骤2以呈现需求为主。明确涉及改色、改结构或改面料的要求，需要作为步骤1的新设计版本确认；不能把未保存设计改动混入展示提示词。对无法可靠判定的自然语言展示待核对项，不宣称自动文本判断能保证服装一致。

### 4.3 详情内容模块

| 分组 | 模块 |
| --- | --- |
| 商品展示 | 主图展示、平铺图、挂架展示、多色组合 |
| 设计细节 | 款式卖点、面料工艺、版型裁剪 |
| 穿搭展示 | 搭配推荐、场景穿搭、博主穿搭、买家秀 |
| 商品信息 | 颜色尺码、规格参数、洗护说明 |
| 品牌与服务 | 品牌介绍、价格优惠、售后保障、常见问题、章节过渡卡 |

- 共19类，默认并排展示6个常用项，其他通过“全部模块”展开；支持基础展示、详情介绍、穿搭展示组合，一键应用前说明会调整哪些数量，不覆盖已编辑规划。
- 未选数量为0；点击未选卡片加为1；加减只调整数量，不冒泡触发卡片二次加减；减到0取消。已选卡片使用轻填充、细边框和数量标记，不仅依赖颜色。
- 顶部显示“已选3类，共5张”。显示数量即目标图片数，每张图片有独立规划；一类多张应有不同视角/构图/卖点，不能复制同一提示词凑数。
- 初始建议每类0–16、单次计划总计最多64张，通过共享配置统一前后端限制；至少覆盖参考里的19张案例。总张数只由模块数量合计，不另设重复总数输入。超过上限就地说明。
- 成分、尺码、工艺参数、价格与售后政策只能使用已有确认资料或用户补充；识图观察与真实事实分开。缺资料的规划标为待补充，明确可生成数和待补数，允许用户显式补齐、移除或仅生成可用项。
- 买家秀/博主穿搭的AI画面不冒充真实评价、真实购买记录或真实人物背书；名称和结果说明保持可识别。

### 4.4 生成参数

常用参数显示图片模型（含供应商）、比例、质量、风格预设和输出文字语言；原生尺寸、自定义尺寸按能力开放。6个文字风格预设平铺，其余折叠。分析模型保持可发现，以紧凑摘要显示；思考默认关闭，仅支持切换的模型显示有效开关，固定推理模型说明其行为。

图片质量、分辨率、比例是不同概念，禁止用统一缩放冒充模型原生高清。图片模型用注册ID引用，参数、图片输入和费用共用现有API适配逻辑；停用或删除模型不再可选。

视角和完整性以模块默认值为基础，可在步骤3逐图调整。统一模特和光线不代表每张图强制同一景别。

### 4.5 分析与右侧反馈

点击“分析商品并生成方案”是显式模型调用，和生图分开确认费用。右侧展示输入已读取、商品特征已整理、整体规范已形成、规划完成X/Y张等真实事件；不伪造百分比、预计时间或展示模型内部思考。

使用现有属性与资料，优先一次分析返回公共规范和各图差异；公共约束不在每张图里重复让模型长篇生成。大计划可按容量分批补齐，已有有效项持续展示。单项失败允许定向重分析，不自动对整套内容无限重试。

分析结果区分已保存属性、图片观察、用户资料、未知/待补项。服务端按所选模块和数量校验结果；流式内容只有通过结构校验后才转成可操作规划。完整校验成功后进入步骤3，断流保留已保存内容并提供继续/重试入口，不把不完整输出显示为完成。

## 五、步骤3：整体规范与逐图规划

### 5.1 页面组织

左侧显示步骤2输入摘要及修改入口；右侧上方显示“整体设计规范”折叠摘要，下方为图片规划。右侧切换“图片规划 / 构图预览”，默认进入图片规划，可收起左栏专注编辑。

每张卡片收起时显示序号、模块、独有标题/摘要、比例、参考图和待补/可生成状态。展开后可编辑标题、画面要求与提示词；支持排序、复制、删除、单项重分析、选择生成及批量应用规范。复制生成新item ID并标为待调整，防止误以为已产生差异方案。复制/删除同步回写模块数量；用户调整数量时保留其他已有编辑，减少数量优先移除未编辑项，并明确选择待移除项。

### 5.2 三层内容与模块化提示词

| 内容 | 职责 |
| --- | --- |
| 图片标题 | 识别用途和组织顺序，不默认当作图内文字 |
| 画面要求 | 用户直接表达本图卖点、构图和展示目标；区别于简短列表摘要 |
| 生成提示词 | 最终发给图片模型的完整文本，可查看、复制和高级编辑 |

提示词按图片目标、服装约束、参考图分工、画面构成、图内文案、本图限制、输出规格分组。模块ID、内部流水号等技术字段留在数据中，用户界面使用可理解的标题。

服务端使用“已保存设计/事实约束＋公共规范＋模块规则＋本图要求＋参数/参考映射”编译实际提示词。界面展示最终文本必须和提交快照一致；不能只在后端悄悄追加另一套不同要求。

最终提示词有自动/手工编辑状态和修订来源。修改画面要求可更新自动部分；已手工编辑时提示对比与合并，不覆盖原文。修改公共规范重新编译相关图片并标记变化，保留逐图手工段和修改历史；显式恢复自动内容可撤销手工编辑。用户不需要反复填写三份表达同一意思的长文本。

参考图编号绑定到引用ID；图内文案独立于管理标题，语言规范只作用于新增文案，商品已有logo、标识、技术单位不强制擦除或翻译。

### 5.3 整体设计规范

规范包含服装一致性、拍摄一致性、版面一致性、语言规则和商品事实约束。默认摘要示例：“中性背景 · 柔和棚拍光 · 简体中文 · 标题靠上 · 服装颜色保持原样”。展开可读、可编辑，并可应用到相关规划。

背景/文字/装饰的配色不能改变服装原配色；统一光线、模特及视觉风格允许不同模块使用不同景别。字体和层级是图片模型的生成指导，不承诺精确字体、像素级排版或人物严格一致。

| 模块 | 默认取景 |
| --- | --- |
| 主图展示 | 主体完整，边缘留白，服装关键部位不被遮挡 |
| 模特穿搭 | 模特身份/体态参考一致，服装完整，姿态自然 |
| 面料/工艺细节 | 允许明确局部特写，AI推演不当作已验证工艺 |
| 平铺图 | 允许无模特，完整平铺，正上方视角 |
| 挂架展示 | 完整悬挂，服装轮廓清楚 |
| 颜色尺码/参数 | 采用已确认资料，清楚对应具体款式和变体 |
| 章节过渡卡 | 允许以文案和视觉元素为主，不强制模特露脸 |

约束优先关系：已确认设计/事实与明确保留项不可被展示风格覆盖；逐图指定取景优先于全局取景默认值；公共风格作用于所有适用图片。白底与非白场景、平铺与必须露脸等明确冲突应就地提示，不让矛盾提示词直接提交。

### 5.4 预览与报价

默认构图示意复用参考图和占位区域，不调用生图模型，明确标为示意。真实低成本试生成可提供为独立操作，使用模型支持的参数、展示费用，并把输出保留为对应规划的真实结果；不默认先付费试生成再付费正式生成。

底栏显示选中可生成张数、待补数和服务端总报价：“已选8张 · 预计XX积分 · 确认费用并生成8张”。支持只生成选中项，既有成功结果不会因返回或改方案消失。报价加载、过期、模型下架、缺资料和价格变化分别处理。

## 六、步骤4与5：任务、结果及历史

- 提交后冻结所用版本、plan修订、全局规范、逐图最终提示词、参考ID/图号映射、模型注册ID、参数及价格。修改草稿创建新修订，不改变运行中快照。
- 每张图显示排队、生成中、成功、失败、待核对；完成一张立即可看。计数分别显示已结束、成功和失败，不把所有结束项统称成功。
- 关闭继续后台运行；重开恢复任务和已保存规划。提交响应丢失先核对原请求，不能自动再提交付费任务。
- 部分成功可进入完成页，失败项单独选择和报价重试；未知结果先核对，禁止盲目重发。
- 结果直接归属款式、设计版本、生成批次与plan item，不新增重复款式卡，不增加一次手动收卡。设封面、切工作版本和另存新款式依旧必须显式操作。
- 当前结果优先，历史按批次折叠/分页，显示版本、模块、时间及成功数；只展开需要的图片，缩略图优先，清晰预览和原图按需加载。
- 支持大图、原图下载、批量下载、设封面、归档/回收站及继续衍生。批量下载处理部分失效文件并明确结果，不把缩略图当原图；删除继续执行共享引用保护。
- 设计版本、规划修订、生成批次分别管理。改提示词、换背景、换模特或再生成不增加设计版本；服装设计变化才另存设计版本。

## 七、状态、数据和服务端设计

### 7.1 数据边界

- 设计版本继续使用 `style_versions` 不可变快照。
- 新增持久化规划对象：所有者、款式/版本、来源图片、输入快照/签名、分析模型/调用记录、状态、当前修订号及更新时间；规划修订保存公共规范、模块数量、逐图内容和手工覆盖。
- 每个plan item使用稳定UUID，保存模块ID、排序、标题、要求、参考映射、取景、参数、提示词状态、最终文本与生成映射；模型输出不得自行决定归属用户或伪造资产ID。
- 生成快照记录规划ID/修订、item ID/修订及实际提示词；原有 `explore_jobs`、`explore_items`、`dna_generations` 与积分账本继续复用。
- 输入草稿与规划持久化按用户隔离；本地缓存仅做加速，不能作为唯一恢复来源。手动编辑采用修订号/乐观锁，冲突保留双方内容，不覆盖别的会话。

### 7.2 状态与失效

| 变化 | 处理 |
| --- | --- |
| 切换设计版本/主体图 | 标记相关规划源已变化，保留旧规划；确认重新分析或新建规划后使用 |

| 改图片模型/尺寸/质量 | 重新做能力和引用校验、失效报价；内容仍适用时无需全套重分析 |

分析状态使用待分析、分析中、部分可用、完成、失败/中断；界面步骤不等同后端状态。生成中允许只读回看；编辑开启新草稿，不通过普通下一步重复提交。

### 7.3 接口与计费

建议接口边界为规划创建/读取、带预期修订的更新、显式分析任务、分析进度/恢复、选择规划项报价、确认提交、按失败项重试报价；具体路径在实施时按现有路由拆分，不把整套规划逻辑继续塞进 `StyleWorkspace.jsx` 或单一路由。

权限、模型能力、引用归属、模块数量、真实参数及提示词编译在服务端校验；分析和生成均有幂等请求标识。分析使用独立聊天/视觉模型及真实token计费；生图使用服务端规格价格、确认后预留和实际结果结算。分析估算和最终用量分别展示，未完成/用量不明确按既有待核对机制处理。

现有款式报价限制1–16且内部批次预置16个候选，必须改为适应规划项数量的款式专用边界，覆盖19张和64张计划；创意衍生现有数量限制不顺带改变。供应商单次输入/输出上限、平台任务并发、计划总数分别校验，复用逐图任务队列限流，不一次并发64个上游请求。

每图有独立提示词与取景，上游输出按item ID归属；不能再对所有图 `Array(count).fill(同一提示词)`。若需要多子任务，服务端统一父批次、幂等及费用，子任务不重复预留。接口选择必须以现有队列和持久化约束验证结果为准。
