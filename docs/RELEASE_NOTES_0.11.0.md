# 0.11.0：设计交付、样衣与制版工作台

日期：2026-10-20（Asia/Shanghai）。代码基线：main / c45800e。

## 使用流程

1. 在设计台打开款式，在“款式衍生 → 三视角与交付”采用正面、背面、侧面原图。可以选当前版本生成图、人工关联原图或上传补图，也支持另一侧与细节图。选图和看图不调用模型。
2. 缺图时选择输出位置，准备生成，核对现有模型、尺寸、质量和服务端费用，再显式确认。各位置共用基准图，分别保存取景及生成来源，沿用持久任务、积分预留、退款和失败重试。
3. 人工核对结构、颜色、图案及补全结构，再确认交付。系统自动建立一个关联样衣项目；同图字节不能重复充当不同视角。后续交付显示待采用，不覆盖当前生产依据。
4. 样衣台仅分为“款式资料 / 用料核价 / 打样生产”。补工艺、成衣尺寸、公差、纸样；颜色和尺码自动形成 SKU，数量共用一张矩阵。
5. 从当前项目进入制版台，在“查资料 / 查尺寸 / 算尺寸”维护、查询并采用标准。区分私有人体实测、标准人体号型、成衣尺寸与放码规则；支持 CSV 导入和有版本的确定计算，不从图片推测实际尺寸。
6. 填面辅料单耗、损耗、同单位单价及其他费用，自动预览 CNY 单件和整批成本。确认后保存固定价格快照；缺价不当免费，明确的 0 可以免费。
7. 建立样衣轮次，上传实拍、实际测量、试衣说明和带部位编号的问题。未解决问题延续到下一轮；确认样衣需完整实测口径和问题处理依据。
8. 建立生产批次时核对三视角、工艺尺寸、制版标准、纸样覆盖尺码、面辅料、SKU 数量、当前核价及同技术基准样衣。批次固定全部采用资料，进度记录不会相加冒充成品数量，完成时明确填写验收结论。

## 数据与权限

- 新增 `product_records`、不可变 `product_history`、`product_requests`、`product_files`、`product_file_refs`，复用已有款式、设计版本、原图及任务。已存在的旧款不强制创建项目或伪造三视角。
- 普通项目资料自动保存；本机暂存按账户和项目隔离、24 小时过期。断网保留输入，丢失响应重试复用请求标识；并发冲突要求显式选择，采用本地修改时只合并用户改动字段。
- 项目、实测人体与未发布资料按账户隔离。维护人员发布正式公共资料；发布后修改需新修订。在用项目提示新标准，不自动替换。
- 历史资料按需分页加载；操作者、时间、变更字段及采用来源保留。纸样、样衣、核价和生产有各自的固定记录。
- 附件最大 20MB；支持图片、PDF 和常见纸样文件下载，PDF 可预览。图片原始字节保留，缩略图独立；所有新增引用（含历史）参与权限与删除保护。项目归档可恢复，移除记录不自动清理共享文件。
- 公共标准附件只允许读取实际已发布修订引用的文件，已从草稿移除的私有附件不会随发布泄露。

## 升级与回滚

启动时执行增量建表。存在旧款式、尚无产品资料表时，先用 SQLite `VACUUM INTO` 创建 `DATA_DIR/backups/pre-product-ecosystem-*.db`，再事务建表；重启不重复迁移。自动数据库快照不替代完整文件备份。

部署前停写，使用现有完整备份脚本，目的目录必须在 DATA_DIR 外且尚不存在：

```bash
node server/scripts/backup-style-upgrade.js /actual/DATA_DIR /safe/new-backup-dir
```

脚本备份并校验数据库，同时保留整个 uploads（含新增 `uploads/product-files`）。现有部署工作流已在升级前停止服务、执行完整备份。

需要回滚时先停写并另存当前完整数据，再恢复升级前数据库和 uploads 配套快照，运行对应旧代码；不要只降级代码后继续清理图片。恢复旧快照会舍弃该快照之后的业务写入，须先确认保留范围。发布由 `main` 推送触发现有部署工作流，线上结果以 GitHub Actions 实际执行状态为准；本轮未执行生产回滚。

## 验证与边界

执行记录见 [统一 TODO](PRODUCT_ECOSYSTEM_EXECUTION_TODO.md) 第十五节。CI 增加 `npm --prefix server run check:products`；浏览器套件覆盖设计交付、制版资料、核价、样衣及生产操作。

模型适配验证使用隔离模拟供应商，未调用真实付费模型。实际服装多视角一致性仍需真实模型出图后人工核对；本版本不会声称能自动识别缺失结构或自动判断合体。知识库和生产尺寸不填未经核对的示例，真实资料需由版师维护并发布。在线 CAD、自动生产纸样、ERP 和复杂排程仍在后续清单。
