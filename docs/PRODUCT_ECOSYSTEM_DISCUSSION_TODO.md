## 已确认的产品定义

1. 产品目标是服装从设计、制版到生产的完整生态。
2. 设计台负责设计探索、不可变设计版本和设计交付。交付给样衣台必须包含同一设计版本的正面、背面、侧面三视角图。
3. 样衣台从设计台接收三视角及设计资料，作为量产准备与生产跟进的平台；承载样衣生产资料、工艺要求、面辅料、核价、SKU 属性、生产进度及本款纸样资料。
4. AI 多视角生成与确认属于设计台的交付准备；不在样衣台复制一套设计生成工作区。
5. 制版台是版师专用的知识、数据与标准工具台，核心包括制版知识库、模特尺寸数据、常用尺寸数据及打版计算器。版师制作的纸样应以这里适用的标准为依据。
6. 制版台与设计台、样衣台的关联、标准执行方式与界面已按后续简化方向收敛，最终以统一执行 TODO 为准，不采用此前重复建制版项目或拆分过多页面的建议。
7. 全平台以低门槛、少配置为产品约束。能力分类不等于独立页面；同一款式资料跨工作台关联复用，避免重复建项目、重复填写和多层确认。

## 简化与聚合方案（讨论记录，已收敛）

以下方案已纳入统一执行 TODO，用于收敛前面的能力清单，不增加一套并行实施范围。

- [ ] SIMPLE-01 三个主要工作台保留职责：设计台做设计与三视角交付，样衣台推进打样生产，制版台提供专业标准、尺寸与计算。资产管理作为公共辅助入口，不在各台重复建立图库。
- [ ] SIMPLE-02 同一款式只建立一份可关联的项目资料；从设计台交付自动带入名称、版本、三视角和说明，打开制版台时带上当前款式上下文。
- [ ] SIMPLE-03 样衣台候选聚合为“款式资料 / 用料核价 / 打样生产”三个分区。工艺尺寸、纸样和颜色尺码属于资料；面辅料单价用量直接计算成本；样衣照片、问题、轮次、生产批次与进度集中处理。
- [ ] SIMPLE-04 SKU 由颜色、尺码自动组合，数量用矩阵填写，复杂编码按需编辑；共用同一份数据，不另做必须逐条录入的 SKU 管理流程。
- [ ] SIMPLE-05 制版台候选聚合为“查资料 / 查尺寸 / 算尺寸”。标准发布与适用范围由维护端管理，版师使用时默认带入适用标准；款式应用记录作为当前款式上下文与最近工作，不强制另建制版项目。
- [ ] SIMPLE-06 人体、成衣及放码数据在同一尺寸工作区分清含义；常用表格、示意图与相关计算器可直接跳转，不让版师重复选数据源和手抄数值。
- [ ] SIMPLE-07 版本、资料修订、纸样历史与打样轮次后台准确记录，前台优先显示“当前采用资料”和统一历史入口，不把全部内部版本号变成用户必填参数。
- [ ] SIMPLE-08 普通草稿自动保存；交付、采用生产资料等关键动作明确确认。完整三视角仍为设计交付必需；缺项提示就近显示，不在日常编辑时用全局红框持续报警。
- [ ] SIMPLE-09 模型、输出与费用控件共用并记忆选择，保留用户查看/更换模型及明确费用确认的能力；高级限制、复杂规则按需展开，不静默调用模型。
- [ ] SIMPLE-10 首轮优先常用尺寸表、预置计算器、基础用料核价、简单打样与生产记录；复杂公式编辑器、多级审批、供应商全生命周期、采购库存财务一体化和在线 CAD 编辑继续作为后续候选，不作为基础使用门槛。
