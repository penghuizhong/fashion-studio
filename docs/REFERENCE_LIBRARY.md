# 款式图1与模特图库

## 图1与当前设计版本

商品图区提供“替换图1”按钮，可直接替换主体且不新增图2；额外参考仍使用普通上传。

需求分析默认使用当前选中设计版本的可用成图作为图1，优先该版本的封面，其次该版本最新的可用图片。文件缺失、回收站、已删除和其他版本的图片不会被当作当前版本的默认图。

如果该版本尚无成图，且款式原图仍存在，会明确显示暂用原图参考；都不可用时可直接上传或从图库选择，失效占位不占可见编号或上传额度。旧列表已有一张可用替代图时，会移除失效项并重新编号，提醒核对要求中的图号，原有分析失效后需要重新分析。替换不删除任何历史文件或历史任务。

切换版本会重新选择该版本的默认图，同时保留已选模特。明确从某张历史结果“以此继续衍生”仍使用该张图片，不擅自换成最新图。已保存的图片引用会按 ID 解析，不受前20条图片分页限制。

## 我的模特

在模特图区上传文件会自动保存到“我的模特”，默认名称取文件名，可在已选模特卡片内修改。点击“从模特库选择”，支持按名称或编号搜索，并可跨款式复用。复用同一条记录，不需要再次上传图片。

文件保存在现有 `$DATA_DIR/uploads/studio/`，元数据保存在 SQLite 的 `style_references` 表中，新增 `name`、`kind` 两个字段。沿用现有账号隔离和图片访问检查；重启后仍可读取，备份应覆盖数据库及 uploads 文件夹。没有引入外部存储服务或新的密钥。

旧文件路径不迁移、不重写。升级时按旧方案里的模特角色，将同一账号的 `ref:` 记录归入模特库，迁移可重复运行；其余旧上传仍可从“已上传”选择，作为模特采用后会加入模特库。

## 验证

后端覆盖命名、分类、搜索、账号隔离、数据库重开持久化、旧数据迁移、当前版本匹配及缺失文件跳过。浏览器覆盖失效图1替换、已有图2自动恢复为图1、版本切换，以及模特文件跨款式复用且无重复上传。继续保留商品图与模特图的双图 API 请求回归。
