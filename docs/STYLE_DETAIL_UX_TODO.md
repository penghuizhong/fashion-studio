## 本轮需求与现状

用户希望点击“款式属性”后，在同一弹窗内让图片收缩到左侧，右侧展示属性，改善弹窗切换造成的割裂。当前实现会关闭原图查看器，再打开独立属性抽屉；抽屉混合属性、生成参数、生成操作、定稿和历史记录。

## 一、统一款式详情空间

- [ ] 款式卡、大图及“款式属性”入口统一进入同一个款式详情弹窗。
- [ ] 点击款式卡默认看大图；点击卡片上的属性入口，直接以图文并排模式打开。
- [ ] 大图模式点击“款式属性”，在当前弹窗展开右侧属性面板，图片等比适应左侧；收起属性恢复大图，保持当前版本与编辑现场。
- [ ] 桌面参考约 60% 图片、40% 属性，保障属性栏可读宽度；具体比例与断点讨论后确定。
- [ ] 标题、款式状态、关闭按钮和当前主要操作保持可见；右侧正文滚动，避免属性字段再套独立纵向滚动。
- [ ] 图片完整展示、不裁切；缩略图用于快速预览，原图按需加载，保留实际尺寸、放大查看和原图下载。保存与收卡继续保留原始文件。

## 二、属性阅读与编辑分离

- [ ] 默认以属性值展示，点击“编辑属性”后进入表单。
- [ ] 根据类目将字段分为结构版型、面料与配色、风格与细节等组，避免所有字段无差别平铺。
- [ ] 长细节采用标签或多行编辑，不挤在单行输入框中。
- [ ] 默认突出“待核对”，详细识别信息按需查看；区分未填写、待核对与已人工确认。
- [ ] 修正人工编辑直接显示 100% 置信度的表达：人工确认与模型判断分别标识，不把人工编辑解释成模型重新识别。

## 三、属性、生成与历史分区

- [ ] 右侧采用“款式属性 / 生成图片 / 生成历史”三个标签，保留切换现场。
- [ ] 属性区承载查看、编辑、保存、名称和状态；生成区先选择动作，再展示对应要求、模型与尺寸。
- [ ] 历史区承载版本查看、预览切换、下载、展示图选择和归档；哪些操作本轮新增，待讨论确认。
- [ ] 定稿放在款式状态附近，说明会锁定的内容、允许继续进行的操作及解锁行为。
- [ ] 每个标签突出一个当前主要动作，区分保存、生成、定稿、批量生产的操作层级。

## 四、保存与生成关系

- [ ] 编辑后显示未保存状态，固定操作栏提供取消修改与保存修改。
- [ ] 标签切换不丢输入；关闭时仅对未保存修改提供处理提示，避免无意义确认。
- [ ] 保存成功明确说明“属性已保存，现有图片保持原样”。
- [ ] 生成使用已保存的属性；有未保存修改时要求先保存，避免用户误以为当前输入已参与生成。
- [ ] 换色、换场景、改细节采用中文说明和示例，替换 navy_blue / white_bg 等技术占位词；是否需要自动映射内部值，实施前核对模型契约。

## 五、图片与版本关联

- [ ] 当前预览标明来源参考图或生成版本、生成时间及展示图状态。
- [ ] 当前款式属性与历史图片生成时的参数快照明确区分，不让新属性看起来已经改变旧图片。
- [ ] 点击历史缩略图切换左侧预览，不额外跳出弹窗，且不自动改动当前展示图或款式属性。
- [ ] 归档、复刻等操作提供手机可用的明确入口，避免仅鼠标悬停可见；删除与归档语义及恢复方式待讨论。

## 六、手机布局与可访问性

- [ ] 保持同一详情面板，使用上图下属性布局，不强行左右并排。
- [ ] 属性展开时图片收成上方预览，可主动展开大图；图片收起后不给属性留下过大的固定占位。
- [ ] 固定名称、状态、关闭及底部主操作，适配系统安全区与软键盘。
- [ ] 保留键盘、焦点、Esc、触控及深浅主题支持，区分退出编辑、关闭图片放大与关闭详情。

## 讨论结束时统一收敛

- [ ] 确定桌面比例、手机图片区域和展开方式。
- [ ] 确定属性分组、编辑粒度与未保存修改处理方式。
- [ ] 确定历史版本、当前展示图、归档和删除的边界。
- [ ] 明确人工确认标识与历史置信度数据的兼容方案。
- [ ] 合并后续讨论的待办，消除冲突和重复，确定实施顺序、测试及版本范围，再统一执行。

建议顺序：统一详情弹窗 → 属性阅读与编辑分离 → 保存与生成关系 → 历史版本联动 → 手机适配。此顺序属于当前建议，等待讨论结束后最终收敛。

## 第二轮讨论：把六个操作升级为款式衍生主流程

状态同上：仅记录优化建议，讨论完统一执行。用户明确指出六个操作才是款式克隆的核心生命衍生能力，不能作为属性页底部的一组附属按钮。

### 已核对的实现问题

- 六个操作为一键生图、换色、改细节、出细节图、换场景、再来一张。目前不同 op 没有完整的专属提示词逻辑；无 changes 时主要共用 DNA 渲染。出细节图缺少明确的局部位置/镜头要求，不能仅凭 op 名称保证效果。
- 衍生默认使用 history[0]；当前预览、用户认可的版本与下一次生成底图没有明确统一。没有生成记录时，没有把上传参考图传入该变体路径。
- 当前 DashScope 适配器明确拒绝带底图的图生图，界面未按编辑能力筛选模型；不能把同 seed 或完整 DNA 提示词当作服装一致性保证。
- 采用仅关闭比较窗并刷新，没有显式选择展示图/工作基准；再调只返回抽屉；回退会调用 deleted 评价并删除新图文件。
- 模型、尺寸、质量参数平铺；高清以翻倍尺寸并限制 2048 的方式推算，需按模型支持尺寸和真实能力校验，不能统一承诺 2x 高清。

### 候选交互与功能任务

- [ ] 统一详情右侧主标签调整为“款式衍生 / 款式属性 / 版本记录”，替代上一轮“生成图片”称呼；默认标签由入口意图决定。
- [ ] 六个动作以带简短说明的工具卡呈现，分为基础出图、设计调整、展示出图；选择动作后展开专属设置，一次只有一个主生成按钮。
- [ ] 一键生图明确为按当前已保存属性生成基础图；有参考图时，参考图重绘作为明确模式，按模型能力开放，不静默改变生成方式。
- [ ] 换色提供色块/色号/名称、修改部位及其他颜色保留条件；改细节提供部位、替换/添加/移除和改动说明。
- [ ] 出细节图选择领口、袖口、面料等具体部位与取景；区分真实原图放大和 AI 推演细节，不暗示推演可还原不可见工艺。
- [ ] 换场景明确背景、展示方式/人物等目标，服装保持要求作为约束；“再来一张”区分同条件再生成与主动探索变化，不以换 seed 保证新颖或一致。
- [ ] 左侧明确“本次衍生底图”及来源版本；可选原始参考图、已选生成版本或认可基准，未明确采用前不自动改用最新生成图。
- [ ] 按每个动作校验模型图生图/局部编辑等真实能力，保存来源、修改目标、保留条件和参数快照；不支持的操作清晰说明，禁止静默降级。
- [ ] 先保留文字约束与部位选择；涂抹蒙版、参考强度等高级控制仅在适配器实际支持时开放，不做无效滑杆。
- [ ] 报价基于服务端模型、尺寸、数量和操作能力，区分免费与未配置；显式确认后提交，任务持久化、幂等、进度、失败/未知结果恢复复用成熟的创意衍生机制。
- [ ] 生成结果在同一详情内比较，桌面并排、手机切换；同机位比较可提供滑动对比，不同构图/局部图不默认叠加。
- [ ] 区分保留版本、设为展示图、以此继续衍生、另存新款式；保留多个候选，不强迫一次只选一张。
- [ ] 放弃本次采用不删除原文件；归档、永久删除与真正回退分别定义，明确费用不会因不采用自动退还。
- [ ] 不默认把衍生变化写回款式属性；可单独确认将颜色等变化同步到当前属性，或另存衍生款，保留原款信息。
- [ ] 记录父版本、动作、变化摘要、参数及采用状态，首轮采用可筛选的版本列表，不急于引入复杂树状画布。
- [ ] 未保存属性先处理；生成中允许安全查看与关闭，避免重复提交；底图缺失、跨款式来源、模型能力不符必须服务端拦截。

建议优先级：先修动作真实含义、底图选择和采用/放弃语义 → 统一衍生工作区与专属表单 → 持久任务、报价和版本链 → 按模型能力扩展局部编辑。具体命名、改动强度、批量数量与版本采用规则继续讨论，尚未实施。

## 第三轮讨论：款式卡内的不可变属性版本

用户提出：每张款式卡版本化，每次更改属性克隆出一版，原属性不动。这是用户提出的核心方向；以下保存时机、图片关联和交互规则属于待讨论建议，未最终定案，暂不实施。

- [ ] 每张款式卡作为一个款式容器，内部保存多个设计版本；修改不覆盖原有版本，不默认新增一张款式卡。
- [ ] 从明确的父版本创建可编辑草稿；同一次编辑可修改多个字段，显式保存时才创建一个正式版本，不按每次输入或单字段修改创建版本。
- [ ] 正式版本保存完整属性快照、父版本、修改摘要、创建时间及来源；旧版本保持不变，可从任意历史版本继续衍生。
- [ ] 切换版本同时展示该版本属性与其关联图片；新版本没有生成图片时明确显示“尚未生成”，父版本图片仅标为参考，不能冒充新版本结果。
- [ ] 区分设计版本与生成记录：同一版属性可以生成多张候选，候选保留模型、尺寸、提示词、底图及设计版本快照；同条件再生成不强制创建一版重复属性。
- [ ] 换色、改设计细节通常创建新设计版本；换背景、视角和细节展示通常只增加该设计版本的生成记录。场景字段若改变设计用途而非画面背景，则按设计修改处理，边界继续讨论。
- [ ] 明确当前查看版本、当前工作版本、款式卡展示图及所属版本，不因生成完成、打开历史或创建草稿而隐式切换。
- [ ] 回到历史版本不删除后续版本；若需要从旧设计继续，显式基于它创建新版本，保留分支来源。
- [ ] 另存新款式用于独立设计方向，与卡片内部新增版本分开。
- [ ] 正式版本默认不可修改；定稿可考虑锁定某一版本而不是禁止整张卡继续衍生，具体规则待讨论。
- [ ] 属性版本不复制原图文件，图片只关联引用，继续保留原图；旧数据作为初始版本迁移时不虚构历史属性快照。
- [ ] 同一基准版本发生并发编辑时，不静默覆盖；显示来源与当前状态，允许保留分支或明确选择新的工作版本。

建议交互：版本选择器 → 编辑属性生成草稿 → 查看变化摘要 → 保存为新版本 → 为该版本生成候选 → 选择展示图或继续衍生。首轮版本列表显示“基于哪一版”和变化摘要，分支多时再讨论树状展示。

## 第四轮讨论：模型、风格、用途与参考图片参数

用户询问款式衍生是否加入模型选择及其他可选参数，提出风格方向、参考图片，并提供电商图位及视觉风格选择界面。以下为讨论建议，尚未实施，不把参考界面的平台规则当成已核验要求。

- [ ] 模型选择保留在衍生工作区的公共生成设置，明确当前模型、所属供应商、能力及服务端费用；默认推荐可用模型，允许更换并记住合理选择。
- [ ] 将参数分为“设计变化、图片呈现、模型与输出”三个层次；只有设计变化保存新属性版本，呈现与输出设置进入该版本的生成快照。
- [ ] 设计变化包含颜色、面料、版型、服装设计风格、细节与必须保留项；按当前动作动态显示，不一次展示全部参数。
- [ ] 图片呈现包含背景、布光、构图、姿态、摄影/品牌视觉风格等，与服装本身的设计风格分开，避免选摄影风格时意外改变款式。
- [ ] 视觉风格使用带服装案例的缩略图卡片，提供“沿用底图 / 自动推荐 / 指定风格”，显示实际选择并可撤销；示例是效果说明，不暗示为当前款式的实时预览。
- [ ] 自动推荐不得静默修改设计属性；自动结果的具体风格与参数应在生成快照中记录，设计变更必须先确认。
- [ ] 参考图支持当前款式原始图、选定历史版本、资产库及上传；底图与辅助参考图分开，辅助图可标注仅参考配色、面料、造型或画面风格。
- [ ] 参考作用是请求约束，不能保证模型完全隔离特征；能力不支持多图、局部编辑或参考权重时明确限制，不提供无效参数、不静默降级。
- [ ] 固定本次编辑底图与设计版本，明确参考优先级（明确修改要求优先，保留条件约束其余设计）；冲突需提示处理，不把所有图片和文字无区别拼接。
- [ ] 模型与输出包含模型、支持的比例/像素尺寸、张数及按能力开放的质量档、seed 等高级设置；切换模型时校验失效参数并提示，更新服务端报价后再确认。
- [ ] 风格强度、参考强度、负面提示词等仅按模型真实支持能力开放；避免把一个通用滑杆映射到不等价协议。
- [ ] 增设“出图用途”预设：自由主图、白底商品图、场景展示、细节特写、卖点信息图、尺寸规格图及多色/多款集合图。用途是可复用的图片呈现模板，不与换色/改细节等设计动作混为同一层。
- [ ] 卖点文案、尺码、材质/工艺描述、变体对应图片均使用用户确认的真实资料；资料不足时提示补全，不由图片模型虚构尺寸或看不见的产品细节。
- [ ] 卖点/规格/集合图优先采用可编辑排版层，生成商品视觉与文字排版分开，数字和单位支持准确转换；优先合成已有确认图，避免重生成后款式或颜色漂移。
- [ ] 出图用途预设比例及排版可以编辑，按模型原生尺寸生成，完整保存原图；不在生成后强裁切。平台规则、适用地区和更新时间后续单独维护，不能根据截图宣称平台已适配或合规。
- [ ] 提交前汇总底图、设计版本、动作、变化/保留条件、参考用途、呈现风格、模型、尺寸、张数与费用；所有实际生效设置写入生成快照。

建议首轮优先开放：底图、动作专属参数、模型、支持尺寸、张数、少量视觉风格和辅助参考图；电商用途中的可编辑卖点图、规格图、集合图作为单独能力分阶段评估，避免一个表单堆满所有选项。该分期仍待讨论结束统一确定。

## 第五轮讨论：同行生成参数与结果工作区参考

仅根据用户提供的两张截图分析可见界面，不据此断言同行模型能力、实时生成机制或平台规则。以下为待讨论建议，暂不实施。

- [ ] 借鉴“分组标题＋一句说明＋可选标记”的信息层级，减少模型参数、设计要求和营销内容混排；属性侧栏保持紧凑，避免照搬过高留白卡片。
- [ ] 借鉴实拍/实用/大片等效果描述，将其作为呈现预设，明确布光、构图、修饰等影响，不与款式设计版本或输出分辨率混淆；不暗示自然和质感必然互斥。
- [ ] 套图一致性独立于风格选择，采用明确开关或选项组，声明统一的服装版本、配色、人物、光线等范围，按能力落实参考和参数约束，不承诺像素或款式完全一致。
- [ ] 模型、速度/质量档、宽高比、实际像素尺寸分组并明确含义；截图中的“轻量”语义未明，不照搬含糊标签，不把 1K/2K/4K 统一当作所有模型原生支持。
- [ ] 输出语言仅在包含卖点、规格等图中文字时显示，与界面语言、内部提示词语言分开；文本优先可编辑排版，不改变无文字图片的设计属性。
- [ ] 促销信息仅在用途和目标渠道允许时按需显示，不作为普通设计衍生的固定字段；与真实商品卖点分开管理，不能自动放入要求纯商品展示的图位。
- [ ] 多图上传可借鉴缩略图＋添加入口＋序号，但必须显示底图、细节参考、配色参考等角色，避免把勾选误解为主图选择或输入参考权重。
- [ ] “帮我写要求”作为可编辑的辅助起草：基于已有属性与明确参考提出建议，不虚构材质、工艺、尺码或促销；如调用模型，明确成本和触发，不覆盖用户原文。语音输入作为后续可选能力评估。
- [ ] 借鉴参数区可收起、结果区可扩大及当前批次优先/历史批次折叠，保留用户选择的历史展开状态；根据用户是否主动跟随新任务决定切换，不能抢走正在看的旧结果。
- [ ] 继续沿用桌面左图右参数的既定建议；从同行借鉴输入与结果分区原则，不因截图反转布局。宽屏可扩展为衍生工作台，手机采用步骤/标签切换，不挤成左右双栏。
- [ ] 预览明确区分参考图预览、可编辑排版预览、正在生成及已完成结果；没有模型实时图像输出时，不把它标成实时生图预览，也不在每次改参数时自动收费生成。
- [ ] 结果以批次组织；分别关联设计版本、生成批次和单张图片，允许一个设计版本多批出图、一批多图位，保留各图真实参数、状态及失败恢复。
- [ ] 结果卡默认按用途/数量适配网格或大图，避免整块画布只有一张过小缩略图；支持查看、下载、继续衍生及更多菜单，关键操作文字可见且手机可用。
- [ ] 图片列表首轮优先；自由画板与视频入口作为后续扩展，不挤占当前款式衍生、版本比较与确认操作。

建议优先借鉴：分组层级、可解释的呈现预设、参考图角色、可收起参数区及批次结果。暂不直接照搬：固定清晰度档、含糊质量等级、全局促销字段、实时预览承诺、自由画板和视频功能。

## 第六轮讨论：创意衍生与款式衍生的统一视角及取景约束（高优先级）

用户实际发现创意衍生结果视角、远近不统一，有些服装没有完整显示；款式衍生是否出现同样现象尚未实测。用户提出增加约束视角选项。继续按约定记录讨论，暂不实施。

代码核对：两条路径均使用 image.js 的 DNA 提示词渲染，当前通用后缀为 high fashion photography / studio lighting / ultra detailed，没有独立的朝向、取景范围、主体占比和完整性约束。创意衍生逐图种子不同；固定种子也不能作为构图一致性保证。现有前端 contain 只保证完整显示模型输出文件，无法补回模型未画出的服装部分。

- [ ] 将本项提升为后续统一执行的高优先级基础能力，两条生图链路共用同一套结构化拍摄约束，分别接入各自表单与快照。
- [ ] 在创意衍生的图片生成步骤、款式衍生的呈现设置中提供可见的“视角与取景”区域，不能仅埋入高级设置或依赖用户自己写提示词。
- [ ] 分开设置展示方式（真人/人台/平铺等）、服装朝向（正面/侧面/背面/四分之三）、相机高度/俯仰、取景范围（完整单品/全身穿搭/指定局部）与主体占比/留白；根据展示方式与类目显示有效组合。
- [ ] 首轮用易懂的“标准款式对比”预设，默认正面平视、完整单品、居中、适当留白；真人展示时选择中性姿态，手臂等不遮挡关键结构，同批方案共用设置。具体占比以类目和画幅验证后确定，不承诺模型精确达到百分比。
- [ ] “服装完整”按类目定义：上装含领口、袖口和下摆，裤装含腰头和裤脚，裙装含完整裙摆；完整单品不等于必须显示人物全身。套装需明确仅上衣还是整套，不能用通用全身提示偷换设计范围。
- [ ] 局部特写是用户主动选择的取景模式，与完整服装要求互斥；正面全图无法同时展示后开衩等背部结构，需要显式背面或多视图任务，不在一张图中混用矛盾要求。
- [ ] 背景、布光和展示方式作为可选的批次统一条件，提高方案可比性；风格预设不得悄悄覆盖已经锁定的视角与完整性要求。
- [ ] 兼容用户原始灵感及场景字段，识别正面/背面、全景/特写等冲突并要求澄清或选择优先设置；清理提示词互斥描述，而不是简单附加“不得裁切”。
- [ ] 按模型原生画幅生成，比例与取景联动并显示推荐；不通过后期裁切、拉伸或缩略图放大伪装修复服装缺失，原始输出始终保留。
- [ ] 结构化约束保存到报价、生成快照和请求幂等签名；改变参数须重新报价。失败项重试沿用原快照，修改取景属于明确的新生成，不把新约束静默写入历史重试。
- [ ] 真实模型仍可能不遵守约束；可评估生成后完整性/构图检查，标记疑似不完整供用户核对。此检查不能证明产品真实细节，不自动重生或自动追加费用；“按原设置重试”与“调整取景重新生成”分别提供。
- [ ] 实测覆盖上衣、裤装、长裙、整套服装，以及方图/竖图、正背面和主动局部特写；检查同批朝向、远近和服装边界一致性。模拟接口只验证参数传递和快照，真实构图效果需实际模型图片验收。

本项仅改变图片呈现参数时，不创建新的服装属性版本；图片绑定所用设计版本与拍摄约束。模型提示词约束能减少构图漂移，不能保证所有结果严格一致；支持底图/构图参考的模型可进一步增强控制，按真实能力开放。
